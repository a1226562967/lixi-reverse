# 失败教训总表（五类误判）

> 这一页比任何打法都值钱。每条都是真实发生过的，且**都导致了整轮方向错误**。
> 读法：动手前扫一眼 A 类；出否定结论前扫一眼 B 类；套坐标前扫一眼 C 类。

---

## A 类 · 判层误判（最贵）

| 误判 | 后果 | 正解 |
|---|---|---|
| 拿到 16MB `.sh` 直接上 IDA 啃 | 啃了整晚才发现控制面一行字就写清了职责 | **先花 20 分钟拆控制面**，让它告诉你载荷是什么、谁拉起、要哪些同伴 |
| 花整晚破载荷面卡密 | 最后证明是 Ed25519 服务端签名，客户端无判定逻辑 | 先做三问（本地？有文本？有签名？）再决定动哪层 |
| 把"服务端判决"当"不可破" | 直接放弃一个本来可以重放的目标 | 不可伪造 ≠ 不可复用；先试重放（成本常数） |
| 把 `.sh` 当脚本读 | 拿不到真正的 ELF | 读头 16 字节；`payload.py` 剥载体链 |
| 把 `.ko.sh` 当普通脚本 | 漏掉内核模块 | `payload.py` 解 base64/尾随 gzip 再判 `e_type` |

## B 类 · 判据误判

| 误判 | 后果 | 正解 |
|---|---|---|
| 熵高就判"密文" | 整晚试解一块**混淆指令流** | 先 `top1` 粗筛：熵>7.85 且 top1<1.2% 才是 CIPHER；OBF 的 top1 ≥1.2%（实测 5.53% 那块"绝对加密"其实不是） |
| 熵能分三态 | 把 17MB 伪代码填充当密文 | 熵只分明文/非明文；三分靠 6-gram 唯一率 + 引用密度 + 接受率 |
| 看到一片 `DCB` 判"解不出" | 整条路线走错 | `DCB` 是工具态：先 `reanalyze_range`/`make_code` 再 `decode_instructions` |
| 裸数 ADRP 当引用密度 | 密文也会报出"像代码"的密度 | 只数 `ADRP Rd + ADD/LDR Rn==Rd`（8 条内配对）；且密文区不采信 |
| 工具 `needed` 恒空 / `static` 恒 True 就信了 | 得出"应用没调用任何 libc"的荒谬结论 | `PT_DYNAMIC=2` / `PT_INTERP=3` 被当节处理；两层 PLT 必须映射 |
| 只看单点发现就下结论 | 撞诱饵 | 多次命中 + 语义自洽 + 行为验证 + 反例排除 |

## C 类 · 坐标套用误判

| 误判 | 后果 | 正解 |
|---|---|---|
| 同加固厂商直接套坐标 | 死伤范围套 CG 范围地址 → 全错 | **判据可迁移，坐标一律重推**（同厂商 ≠ 同样本：游戏不同、哈希不同、读写方式不同） |
| 按 `vaddr` 直读 `.data` | 得到"0 条物资"的假否定 | 先建 `v2o()`；实测 delta `0xC000`，修正后 49,110 条 |
| 用旧壳版的 OEP 偏移 | 打错地方 | 每次重新定位；版本号写进账本 |
| 把数据表里的编号当凭证 | 追错目标 | `PASS-90xxxx` 是物资 ID，不是卡密 |
| 直接信 dump 体的 `e_entry` | 找不到 main | 走 `__libc_init` 的 `x2`（slingshot） |

## D 类 · 工具/工程误判

| 误判 | 后果 | 正解 |
|---|---|---|
| 手搓 APK v2 签名 | 试了 18 种变体两个样本全对不上 | 用 `apksigner` 或 MT 管理器；`v2parse.py` 只用于验证理解 |
| 自己用 zipfile 重打包整个 APK | STORED `.so` 不对齐 → 装不上/装上就崩 | 只替换单个文件，让工具处理对齐+签名 |
| 改签名直接覆盖安装 | 同包名不同签名不能覆盖 | 先卸载（会丢数据） |
| 改完不读回 | 说不清原字节的人一定会改错 | 写前校验 + 写后读回 |
| 扫中文串不过滤 | 51,239 条"CJK" 几乎全是二进制误判 | NUL 分隔 + 字符白名单比例 ≥75% 两道过滤 → 剩 25 条 |
| 自己的密码实现不过测试向量 | 分不清"算法写错"还是"密钥取错" | 先过 FIPS-197 C.3，再解目标 |
| 抓包脚本没有 trap | `kill -9` 后 iptables 残留 → "手机没网了" | `trap` + 收工前 `iptables -t nat -L OUTPUT -n` |

## E 类 · 结论边界误判（最伤信誉）

| 误判 | 后果 | 正解 |
|---|---|---|
| 把"钩到了/解出来了/分析跑通了"当交付 | fake 结果 | 唯一交付 = **用户亲眼看到主程序/真功能**，或**带 ≥2/4 验证的明文产物** |
| 把 inference 当下一步前提 | 连锁错误 | 证据三级：observed / inference / unknown；inference 必须先验 |
| "这块我解不开" = "它是加密的" | 掩盖缺件 | 缺件如实报：缺什么（名字+版本）、卡在哪步、有哪几种拿到 |
| 只用半自动/肉眼结论当证据 | 把 `\xe6\xa1\x82` 读成"桃"（实为"桂"） | 关键字符用字节核对 |
| 把"弹窗内容变了"当成功 | 从一种错误变成另一种错误 | 判据是"能不能进主程序"，不是"错误提示变没变" |
| 拿绕行冒充脱壳 | 交付无效 | 脱不动就报"卡在第几层 + 什么机制 + 已试工具清单" |

## F 类 · 运行时打桩误判（起源 3.1 实测）

| 误判 | 后果 | 正解 |
|---|---|---|
| **全量 `bl` 扫描 0 命中就判"死代码/诱饵"** | 差点放弃真正有 12 个补丁点的样本 | 虚函数/函数指针/回调/`.init_array`/JNI 注册表**都不产生 `bl`**。先查 `.rela.dyn` 与 `data.rel.ro`（`rkprobe` 判据 5） |
| **capstone 没开 `skipdata`** | 全量扫描只解出 2,773 条（实际 236 万条），以为"程序很小" | 第一个非法编码就停了。**全量扫描必须 `md.skipdata = True`** |
| **`adrp` + `add/ldr` 配对写错** | 字符串 xref 全 0 命中 | `add` 第三操作数是 `imm`、`ldr` 是 `mem.disp`，两种分开处理。**0 命中先怀疑脚本** |
| **把用户态 PIE 当 `.ko` 分析** | 按内核模块思路折腾半天 | `e_type=3(ET_DYN)` ≠ `1(ET_REL)`；NOTE 里有 `Android`/`r29` → NDK 编的用户态 PIE |
| **假设所有跳板指向不同函数** | 解出 6 个跳板全指 `0x8a50`，以为解错了 | 共享解密入口 + 每函数 16 字节密文块（ID+加密指令）。**异常一致的结果先别否定，可能是设计** |
| **返回值方向搞反** | 把"返回 1 = 成功"改成 0 → 反而不通过 | `cbz w0,<成功>` → 0 成功；`cbnz w0,<成功>` → 非 0 成功。**先读调用者再决定值** |
| **只打返回值不写 out 参数** | "过了但显示 2038 之前/垃圾日期"，或触发二次校验 | 函数原型带 `x1` 指针一律当 out 处理（B2 的 16 字节） |
| **有服务端副本的判定也去打桩** | **封号** | 300s 心跳/周期上报不要整体 RET；只改本地消费端，保留真实上报 |
| **改"检测代码"而不是"被检测的值"** | SIGSEGV（破坏栈/寄存器依赖） | `.bss` 标志喂狗；改写入点实测崩 |
| **ptrace attach 去改内存** | 反调试立刻发现 | 走 `/proc/pid/mem`，不产生 `TracerPid` |
| **一次把所有点打完** | 出问题不知道是谁，且触发初始化覆盖 | 用输出门分阶段，一次一批 |

## 一条总纪律

> **任何"0 命中"的否定结论，先怀疑自己的取址/工具/过滤，再怀疑目标。**
> 尤其当这个结论正好**符合你当时的猜测**时 —— 那才是最该怀疑自己的时候。
