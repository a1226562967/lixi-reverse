# 网络硬依赖：合成响应 vs 入口整段跳过

> **"联网能跑、断网崩"不是授权门，是程序把网络响应当必需输入。**
> 破它只有两条路：**喂它一份合法的假响应**（要对齐全链路 + 对象生命周期），
> 或**在入口整段跳过网络段**（一条 `B`，前提是栈帧处于零页）。
> 实测：LV 追锁最终形态 = **v9 一条 `B` 指令**，飞行模式下也能起主程序。

---

## 一 · 先读崩溃文案（这张表决定排查方向）

| 运行时报错（原样） | 真正含义 | 下一步查什么 |
|---|---|---|
| `std::invalid_argument: stoi: no conversion` | 某处把**非数字串**喂给 `std::sto*` | 找 `sto*` 调用点：十六进制解码、时间戳、`Content-Length` 解析 |
| `parse_error.101 … attempting to parse an empty input` | 解析器拿到**空串** | 上游字符串没构造成功，或 flag/长度字段被清零 |
| `parse_error.101 … invalid literal; last read: 'XX'` | 解析器拿到**非预期字节** | 上游不是你以为的那份数据（可能 use-after-free 的残留堆） |
| `type_error.302 … type must be string, but is …` | JSON 解析成功但**类型不符** | 少字段/类型错 → 补全 JSON 字段 |
| `IllegalStateException: SHA-256 校验失败：<64 hex>` | 打印的是**实测值** | 期望值在清单或硬编码里（见 `02` §壳加载器） |
| `Aborted (exit 134)` + 之前一片重试日志 | 自己的错误路径重试耗尽后 abort | 先修真正的失败条件（如找不到目标进程） |

**两个通用反证技巧**：
1. **同一操作在线/离线表现一致** ⇒ 说明补丁已生效（两边走同一条本地路径）。
2. **联网能过、断网不能** ⇒ 问题在"响应"这一侧，不在授权判决本身。

**符号链定位**（不用 IDA 也能跑）：

```
__throw_invalid_argument（引用 _ZTISt16invalid_argument 的那个小函数）
  ← 被两个静态函数调用（stoul / stoi 各一个）
    ← 它们的调用点 = 真正的业务位置
```

自建 ADRP+ADD/LDR 扫描（`scripts\rkprobe.py` 已有该能力）比全量反编译快一个数量级。

## 二 · 路线 A：合成响应（让整条链自己跑通）

先摸清**整条解码链**，别假设它是 `hex → JSON`：

```
原始响应串 → 十六进制解码（每 2 字符 strtol(base=16)）
           → 对称变换（实测是标准 RC4：S 盒 0..255 + 标准 KSA + out = in ^ S[(S[i]+S[j])&0xFF]）
           → json::parse
```

- 逐层确认：出现 `strtol`/base 16 → hex；出现 256 项 S 盒 + 交换 → RC4
- 密钥就在同一函数附近的字面量里；**密钥长度看字符串对象的 size 字段**，不要数引号里的字符
  （实测：看着 31 字节，按 31 硬算就 `stoi: no conversion`）
- 合成：`响应体 = hex( RC4(key, 明文JSON) )`

> **这条路真正的难点不是加密，是对象生命周期**：响应串/解码结果/变换结果都是**局部临时对象**，
> 析构顺序与 `parse` 的取用时机必须对齐。把 `parse` 输入指向"已析构但指针还在"的槽 ⇒ 解析到回收堆垃圾，
> 报错看着像"格式不对"，实际是 use-after-free。**改一个指针之前先确认那个对象还活着。**

## 三 · 路线 B：入口整段跳过（推荐，通常一条指令）

思路：在 `main` 序言之后插一条 `B <网络段之后的第一条指令>`，把公告 / 更新 / 登录**整段跳过**。

### 为什么安全（关键判据：栈零页前提）

> **`main` 由 `__libc_init` 调用一次**，其大栈帧（几 KB～几十 KB）所在栈页是**首次触碰的新映射零页**。
> 于是被跳过的所有局部对象在退出清理时都是**零值**：
> - 自定义/SSO 字符串：`flag=0` ⇒ 空串 ⇒ 不 `free`
> - `nlohmann::json`：`type=0` ⇒ null ⇒ 析构 no-op
>
> 所以"整段跳过导致析构未初始化对象"在零页前提下**不成立**。
> 反面：在**已用过的栈槽**上手工拼半成品对象（写 flag/size/ptr 却不保证生命周期）= 自造 use-after-free。

### 选跳点

序言之后、第一条"建串/发请求"指令处 → 目标 = 网络段之后的第一个已知锚点
（实测是 `"starting (ImGui %s)"` 那条日志之前）。跳完保留后面所有真实初始化（菜单、驱动连接）。

### 验收

设备上跑，日志里**再也没有任何网络相关输出**；**飞行模式与联网表现完全一致**。

## 四 · 两个必踩的坑

1. **stdout 是缓冲的**
   `abort()` 不会 flush ⇒ 崩溃前打过的日志可能全部丢失。
   **不能用"没看到某行打印"来证明"没走到那一步"。** 要证据就加
   `setvbuf(stdout, NULL, _IONBF, 0)` 或改用写文件 / `__android_log_print`。

2. **"改了没生效"先怀疑安装**
   APK 同 `versionCode` 会被国产 ROM 安装器**静默跳过**；先确认"装进去的确实是我这一版"
   （`versionName` + `versionCode` 一起改，并换新文件名），再谈补丁对不对。
