# 验证闭环 — 怎么证明"真的过了"

> **手段完成 ≠ 交付。** 明文 dump 落地、壳层脱净、"分析跑通了"、报错弹窗从一种变成另一种 —— 都不算成功。
> 本文件定义每条路线的**可观察证据**，以及验证失败时怎么还原。

---

## 一 · 四条路线各自的"过门"标准

| 路线 | 唯一可观察证据 | 常见假阳性（不算） |
|---|---|---|
| **A · 控制面补丁** | 重打包/重签名后装机，**用户亲眼看到主界面 / 真功能可操作** | "dex 改了" / "反编译看着对" / "算出来的 verified=true" |
| **B · 载荷剥离/脱壳** | **明文产物落盘** + ≥2/4 验证 + provenance | "hook 到了" / "内存里能读" / "字符串解出来了" |
| **C · 服务端重放** | 断网或指向不存在服务器时，**能进主界面**（用户看到） | "抓包成功" / "假服务器返回 200" / "重放库装上了" |
| **D · 特权面** | **能力面表 + 证据等级**（不宣称"破解"） | "我觉得它是外挂" |

---

## 二 · 脱壳/剥离的 ≥2/4 验证

任取两条成立才算"剥成明文"：

| # | 验证 | 怎么做 |
|---|---|---|
| 1 | **strings 增量** | 剥离后能读到原本读不到的明文串（UI 文案 / URL / 错误信息） |
| 2 | **imports 变真实** | 原本 `imports=0` / 不可解析，剥离后能列出 `libc.so` 的符号表 |
| 3 | **capa/反编译命中上升** | 反汇编接受率上升、能连续解出合法指令、xref 密度回到代码基准 |
| 4 | **能跑** | 在设备/仿真上跑起来（无设备时用 unicorn 按 entry 仿真到第一个 syscall） |

**provenance（必记）**：第几层、用什么方法、偏移多少、产物 sha256。示例（`payload.py` 自动输出）：

```
provenance:
  4.9.186.sh    --trailing-gzip@366  -> 93c33c68bd07a5769036f710fb6c52b3 (389648 B)
```

> **没有 provenance 的产物不可复现**：下周你或别人再看，说不清这个 ELF 是从哪剥出来的。

## 三 · 补丁的验证（路线 A）

```
1. 写前校验原字节（assert d[fo:fo+4] == 期望原字节）
2. 写后读回，再核一次（patch_dex.py 自动做）
3. 记录：文件 / 偏移 / 原字节 / 新字节 / sha256
4. 重打包（别自己打 zipfile）→ 重签名 → 卸载旧版 → 安装
5. 启动 → 用户亲眼看到主界面 / 功能可用
```

**失败分支怎么判**：

| 现象 | 说明 | 下一步 |
|---|---|---|
| 装不上 | STORED `.so` 没页对齐 / 签名不对 | 换 MT 管理器或 apksigner；查 `compress_type` |
| 装上闪退 | 改坏了指令长度 / 触发完整性校验 | 回滚，改用等长 `nop`；查 `getPackageInfo/signatures` |
| 能进但功能异常 | 只改了显示层或漏了某条路径 | 往上找总闸门（`xxxOrYyy`） |
| 弹窗文本变了但还是进不去 | 撞到下一道门 | 逐门建档，不跳门 |

## 四 · 重放的验证（路线 C）

```
1. 装好四件套（收发 hook / 顺序匹配 / 随机数回放 / 时间冻结 + 反检测）
2. 断网，或把目标指向 127.0.0.1（不存在的服务）
3. 启动 → 能进主界面 = 成功；卡在"网络错误/请检查网络" = 请求没被截到
4. 再验一次反向：连回真服务器、卡已过期 → 应该失败（证明你的成功不是巧合）
```

**失败模式对照**（详见 `05-server-verdict.md` §七）：

| 现象 | 原因 |
|---|---|
| 第一次能用，第二次失效 | nonce / 一次性 token / 新鲜度 |
| 客户端报"签名错误" | 你动过响应字节（必须**原样**回放） |
| 卡在登录前 | 请求没匹配上（顺序错 / 用了 `read` 而没 hook `recvmsg`） |
| 检测到注入直接退出 | 反检测没做（maps / dl_iterate_phdr / environ） |

## 五 · 改动台账（必须写，否则污染后续所有测量）

任何"改内存 / 改字节 / 改环境 / 改封包"都要记四件事：

```
改了什么:      文件/偏移/原值→新值（或 环境变量/代理/iptables 规则）
污染哪些测量:  这次改动会让哪些后续判据失效（例：改了时间 → 所有"剩余天数"显示不可信）
怎么还原:      具体命令或备份路径
还原验收:      还原后读回/hash 对齐的证据
```

**无效果必还原**：伪造参数若无效果或不确定，**立刻还原原值 + hash 对齐**，再换路线。
残留修改会让下一轮把"上一次的副作用"误判成"目标的行为"。

**抓包环境的卫生**：
- 手机侧 iptables 规则由脚本 `trap` 清理；`kill -9` 后规则残留 → 表现为"手机没网了"。
- 收工第一条：`iptables -t nat -L OUTPUT -n` 看清楚有没有残留 REDIRECT。

## 六 · 恢复原状清单（收工前）

```
[ ] 补丁：还原原文件（有备份 + hash 对齐），卸载测试版
[ ] 设备：卸载 hook 库 / 清 LD_PRELOAD / 恢复 iptables / 删除 /data/local/tmp 下的落地物
[ ] 环境：恢复代理/DNS/hosts（如果你动过——本工位要求不动）
[ ] 案件：attempts.md 写最后一轮结论；milestones 记 [OK]/[X]
```

> **不还原 = 下次开局就在一个被污染的环境里**，而且你可能忘了自己改过什么。

## 七 · 结论怎么写

```
结论: 通过 / 未通过 / 卡在第 N 层
证据: 可观察事实（谁看到什么、哪个文件哪个字节、返回了什么）
证据等级: observed / inference / unknown
缺口: 缺哪份输入（设备 / 有效卡 / 一次抓包 / 某个 .so）
```

**禁止**：把"分析跑通了""反编译成功""弹窗内容变了"写成结论；
把"应该可以""大概能"当成 observed。
