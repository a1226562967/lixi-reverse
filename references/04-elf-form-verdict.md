# 形态判定与密钥打桩（代码 / 伪代码 / 密文 三分）

> **熵只能分开"明文 / 非明文"，分不开「真代码 / 伪代码填充 / 密文」三种非明文。**
> 判错形态的代价是整晚试解一个不存在的东西。本文件给三条与算法无关的数值判据 + 密钥打桩识别。
> 配套：`scripts\elfprobe.py` 已把①③②全部实现并打印。

---

## 一 · 三条判据的定位

| 判据 | 测什么 | 成本 | 角色 |
|---|---|---|---|
| **① top1 字节占比** | 4KB 块最高频字节的占比 | 秒级 | **粗筛** |
| **② 6-gram 归一化唯一率** | 连续 6 条指令是否反复出现 | 分钟级 | 确认 |
| **③ ADRP 引用密度** | 每 MB 有多少"ADRP + ADD/LDR 配对" | 分钟级 | 确认 |
| （④ 反汇编接受率） | 能否连续解出合法指令 | 分钟级 | 辅助（有 DCB 陷阱） |

**顺序：先粗筛，再确认。** 反过来会把时间浪费在反汇编一块根本不是代码的东西上。

## 二 · ① 最便宜的一维：`top1` 字节占比

```python
def top1_profile(d, bs=4096):
    out = []
    for o in range(0, len(d) - bs + 1, bs):
        blk = d[o:o+bs]
        cnt = [0]*256
        for x in blk: cnt[x] += 1
        out.append(max(cnt)/len(blk))
    return out
```

| 结论 | 判据 |
|---|---|
| **CIPHER（真密文）** | 熵 > **7.85** 且 `top1 < 1.2%` |
| **OBF（混淆指令流）** | 熵 > **7.5** 且 `top1 ≥ 1.2%` |

理由：均匀分布时每字节理论值 1/256 = **0.39%**，AES/ChaCha 输出接近这个数；
指令流即使被插花/随机化，高频操作码（`NOP`/`MOV`/`RET` 的字节）依然重复出现，实测 **2%–6%**。

实测反例（关键）：某块区域熵 7.99、看起来"绝对加密"，但 `top1` = **5.53%** → **不是密文**（是混淆指令流）。

## 三 · ② 6-gram 归一化唯一率

测什么：真实编译产物有大量重复惯用法（函数序言 `stp x29,x30,[sp,#-N]!`、`ldr`+`bl` 模板、错误处理骨架），
所以"连续 6 条指令"在真代码里必然反复出现；密文和"逐条随机生成"的伪代码**永远不会重复**。

**必须归一化**（掩掉地址/偏移位）：

| 指令 | 掩掉什么 | 掩码 |
|---|---|---|
| `B` / `BL` | imm26 | `w & 0xFC000000` |
| `B.cond` | imm19 | `w & 0xFF00001F` |
| `CBZ/CBNZ` | imm19 | `w & 0x7F00001F` |
| `TBZ/TBNZ` | imm14 | `w & 0x7F00001F` |
| `ADRP` | immlo+immhi | `w & 0x9F00001F` |
| `ADD/SUB imm` | imm12 | `w & 0xFFC003FF` |
| `LDR/STR imm12` | imm12 | `w & 0xFFC003FF` |
| `LDR/STR imm9` | imm9 | `w & 0xFFE00C00` |

`MOVZ/MOVK` 的立即数**要留**（常量本身是指纹）；`0x0` 与 `NOP` 先剔掉（填充噪声）。

```python
def norm(w):
    if (w & 0x7C000000) == 0x14000000: return w & 0xFC000000        # B/BL
    if (w & 0xFF000010) == 0x54000000: return w & 0xFF00001F        # B.cond
    if (w & 0x7E000000) in (0x34000000, 0x36000000): return w & 0x7F00001F  # CBZ/TBZ
    if (w & 0x1F000000) == 0x10000000: return w & 0x9F00001F        # ADR/ADRP
    if (w & 0x1F000000) in (0x11000000, 0x51000000, 0x91000000, 0xD1000000):
        return w & 0xFFC003FF                                       # ADD/SUB imm
    if (w & 0x3B000000) in (0x39000000, 0x3D000000): return w & 0xFFC003FF
    if (w & 0x3B200000) == 0x38000000: return w & 0xFFE00C00        # pre/post index
    return w

def uniq_ratio(blk, n=6):
    ws = [norm(struct.unpack_from('<I', blk, a)[0]) for a in range(0, len(blk)-3, 4)]
    ws = [w for w in ws if w not in (0, 0xD503201F)]
    if len(ws) < 128: return None
    g = {tuple(ws[i:i+n]) for i in range(len(ws)-n)}
    return len(g) / (len(ws)-n)
```

**阈值（实测标定）**：

| 样本区域 | 唯一率 | 判读 |
|---|---|---|
| 原版 192 KB 壳桩 | **0.373** | 真代码 |
| 破解版前端 1.16 MiB | **0.506** | 真代码 |
| 破解版 17 MB 伪代码 | **1.000 / 0.979** | 非代码 |
| 原版 42.6 MB 主体 | **1.000** | 密文 |

> **`< 0.75` = 代码；`0.75–0.97` = 混合；`> 0.97` = 不是编译产物。**
> 换算成"每 MB 有多少条能连着比"，比看熵直观得多。
> `elfprobe.py` 实测：43MB 加固体 = **0.970**（混合/密文边界），VS 310KB 自解密载荷 = **1.000**。

## 四 · ③ ADRP 引用密度（最省事、最不易伪造）

正常 C++ 程序平均**每 200 字节**就有一条 `ADRP + ADD/LDR` 去取字符串、全局变量、跳表地址
⇒ 引用密度天然落在**每 MB 数千处**。密文 **0**。伪代码填充只在少量模板里有引用 ⇒ **每 MB 几十处**。

```
代码        ≈ 5000–5200 /MB     （实测 5193/MB）
伪代码填充  ≈ 50 /MB            （差 100 倍）
密文        0
```

**必须用"配对"而不是裸数 ADRP**（重要实现细节）：

```python
# 只有 ADRP Rd 之后 8 条内出现 ADD/LDR Rn==Rd 才算一次真引用
is_add  = (w & 0xFF800000) == 0x91000000          # ADD (imm, 64bit)
is_ldst = (w & 0xFFC00000) in (0xF9400000, 0xF9000000, 0xB9400000, 0xB9000000)
pair = (rn == last_adrp_rd) and (is_add or is_ldst) and (i - last_i <= 8)
```

为什么：裸数 ADRP 在密文上会被随机命中污染 —— 实测 43MB 加固体裸数 **150,266** 条 ADRP（全是噪声），
配对后仍有 3736/MB，**仍高于代码基准**。所以这一维必须配合形态判据才敢采信：

```python
trusted = (uniq is None or uniq < 0.9) and entropy_mean < 7.6
# 不 trusted → 输出 "XREF-NOT-TRUSTED"，不给结论（宁可不说，也不给假数值）
```

## 五 · ④ 反汇编接受率 —— 先拆掉 `DCB` 陷阱

**陷阱本体**：IDA 的 `decode_instructions` 对**尚未被标记为代码**的字节直接回 `DCB 0x??`。
它**不代表解不出指令**，只代表"IDA 现在认为它是数据"。

正确用法（三步，顺序不能换）：

```
① 先让工具把区间认成代码 → reanalyze_range(start, end) / make_code(addr)
② 再 decode_instructions(addr, N)
③ 读"连续合法条数"与"夹在中间的 DCD/DCB 比例"
```

| 观察 | 含义 |
|---|---|
| 连续几十条全合法，`DCD` 罕见 | 真代码 |
| 能连解 ~20 条，然后固定夹几个 `DCD`/乱码，周而复始 | **伪代码填充 / 指令级混淆** |
| 一个都解不出（且已 make_code） | 密文或压缩 |

> 实测伪代码填充的规律：`MOVZ/MOVK 造 32 位常量 → STR [SP,#8] → BL`，后面固定跟 3 个乱码字，**32 字节一周期**。
> capstone 侧实现注意：`md.skipdata = True`，否则遇到非法编码会抛 `CsError`（密文必然触发）。

## 六 · 三分矩阵（一张表定形态）

| 形态 | ① 6-gram 唯一率 | ② 反汇编接受率 | ③ 引用密度 | top1 |
|---|---|---|---|---|
| **真代码** | < 0.75 | 高（连续合法） | ≈5000/MB | 低熵区无所谓 |
| **混合（代码+数据+桩）** | 0.75–0.97 | 中（周期夹坏） | 中 | — |
| **伪代码填充** | ≈1.0（0.979–1.000） | 定期夹坏 | ≈50/MB | — |
| **密文** | 1.000 | 全坏 | 0 | 熵>7.85 且 <1.2% |
| **混淆指令流** | 可 <0.9 | 中 | 中 | 熵>7.5 且 ≥1.2% |

## 七 · 密钥派生打桩（"密钥从哪里交出来"与"加密多强"正交）

### 7.1 三种打桩形态

| 形态 | 长相 | 判读 |
|---|---|---|
| **常量即密钥** | `mov w0, #0xA5; ret` | 返回值参与异或/查表/长度计算 = **密钥** |
| 布尔桩 | `mov w0, #1; ret`（只被 `cmp #0` 消费） | 是开关，不是密钥 |
| 派生桩 | 读固定全局/常量表再算 | 追到那个全局/表 |

### 7.2 看到 `mov wX,#imm; ret` 先看调用者，再定性

| 调用者侧的行为 | 结论 |
|---|---|
| 返回值进 `eor` / 查表索引 / 长度计算 / 作为 key 送给 cipher | **密钥**（这就是破解点） |
| 返回值只被 `cmp #0` / `cbz` 消费 | **布尔桩**（改它 = 改开关，效果取决于它守什么） |

**实证（CG 范围）**：`0x10B94` 返回 `0xA5`，配 51 字节密文 `94 c3 95 97 …`，一次 XOR 就出
`?qq_aio_chat_type=2` —— 云端配置地址。三行 python 验证：

```python
ct = bytes.fromhex('94c39597...')          # 51 字节
print(bytes(b ^ 0xA5 for b in ct))         # b'?qq_aio_chat_type=2'
```

### 7.3 "判定厚度"是第二个判据

某函数被调用五次，全是 `cmp x,#0`（0x14440/0x14454/0x14468/0x1447C…），
**不验内容、不验签名、不验时间** ⇒ 这是"薄判定"，改一处常量就能过；
反之若它还哈希了内容/校验了签名/比对了时间 ⇒ 改常量只会撞下一个门。

### 7.4 从消费点反推（不识别算法也能定位密钥）

```
不找"加密函数"，找"谁在消费解密出来的东西"：
  消费点 ← 它读的那个缓冲区 ← 谁写的缓冲区 ← 写入循环里的 key 寄存器 ← 那个 key 从哪来
```

## 八 · dump 体五指纹（拿到的不是原版，是内存 dump）

| # | 指纹 | 含义 |
|---|---|---|
| 1 | `vaddr == p_offset`（所有段） | 按 vaddr 平铺 dump 的典型形态 |
| 2 | **无节表**（`shnum=0`）或节表明显残缺 | dump 通常不带节表 |
| 3 | `e_entry` 失效 / 指向不可执行区 | dump 后入口常错 |
| 4 | 尾部追加段（`offset+filesz` 超过原文件尾） | 追加的 payload / 第二层 |
| 5 | 段权限错标（`.data` 段标成 `R+X`） | dump 工具按内存页属性写回 |

> **找 main 别信 `e_entry`**：走 `__libc_init` 的 `x2`（slingshot）。"永远别信 dump 体的 e_entry"。
> 实测陷阱：工具 `needed` 恒空 / `static` 恒 True → 因为 `PT_DYNAMIC=2` / `PT_INTERP=3` 被当成"节"处理了；
> **两层 PLT 必须映射**（`bl 0xFED0+ → GOT 0x13B4E0+ → 0x760xxx`），否则会得出"应用没调用任何 libc"的荒谬结论。

## 九 · 算法族排除顺序 + 止损线

试解之前先排除（顺序固定，每步 2 分钟）：

```
1. 标准压缩？  lzma / xz / zlib / gzip / bz2 / zstd / lz4       → payload.py 已内置扫描
2. 单字节 XOR？取密文高频字节与明文空间期望互信息（英文/UTF-8 分布）→ 命中率 > 60% 即成立
3. 固定周期 XOR（4/8/16/32/64/256）？按周期切块做卡方                  → 实测全 1.000 排除
4. 分组密码（AES-128/256 × ECB/CTR(be,le)/CBC(iv=0)）？              → 全 1.000 排除
5. 静态特征：S 盒首字节 `0x63`、`Te0` 表、`0x67452301`(MD5初值)、`0x6a09e667`(SHA256初值)
```

**止损线**：以上全 miss 且没有能跑它的机器 → **停手出定性结论**，不要再试第 7 种算法。
"这块不是标准密码（自研位流/VM）"本身就是一条有价值的结论，它会把你导向 §7（找密钥源）而不是继续试解。

## 十 · 加密形态 × 静态特征 × 密钥形态（换算法对照）

| 加密形态 | 静态特征 | 密钥形态 | 打法 |
|---|---|---|---|
| 单字节 XOR | 熵偏低（5–6.5） | 一个 imm 常量 | 直接爆破（256 次） |
| 固定周期 XOR | 6.5 左右，块间相关 | 小常量表 | 按周期切块 |
| AES 系 | 熵≈8、S 盒/Te0 表 | 32/16 字节，常在 static_values 或 `.rodata` | 找密钥 → 纯 Python 复现 |
| RC4 / ChaCha | 熵≈8、S 盒初始化循环（256 轮） | 同上 | 同上 |
| 自研位流 | 熵 7.5–7.8、标准流全 miss | 可能是个常量种子 | 找骨架（LZ 三件套）或找桩 |
| 平台 VM | 熵≈8 + 平坦化四判据 | **无密钥**（是解释器） | 找 handler 表；不要试解 |
| 服务端下发 | 本地无解密代码 | **无** | 转 `05-server-verdict.md` |

## Checklist

```
[ ] 形态判型先做：top1 粗筛 → 6-gram 确认 → 引用密度 → 反汇编接受率
[ ] 任何"解不出/DCB"结论，先 reanalyze_range/make_code 再说
[ ] 引用密度只用"配对"计数，且只在非密文区采信
[ ] 找密钥：看"谁交出来"，不看"算法多强"
[ ] mov wX,#imm; ret 先看调用者：进 eor/查表=密钥；只被 cmp #0 消费=桩
[ ] 判定厚度：几层 cmp、验不验内容/签名/时间
[ ] 拿到 dump 体先过五指纹，找 main 走 __libc_init 的 x2
[ ] 试解止损：算法族排除 5 步全 miss 就停，出定性结论
```
