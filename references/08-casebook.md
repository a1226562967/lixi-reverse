# 案例库（九个真实样本）

> 每块给：样本形态 / 锁在哪一层 / 用什么判据判出来的 / 实际动作 / 结果 / **可迁移** / **不可迁移** / 教训。
> 读法：先看"锁在哪层 + 判据"，坐标一律不可照抄（见 `09-anti-patterns.md` C 类）。

---

## 1 · 止痛药 5.86（APK 层 · 两字节）

- **形态**：未加固 APK，dex 20MB+11MB+10MB+6MB + **一个 2292 字节的 classes5.dex**；字符串 AES-GCM 混淆（前缀 `f1:`）
- **锁在哪层**：控制面 · **本地 JSON 字段 `ok`**
- **判据**：① 解码器四特征全中（`String→String` + `substring(3)` + `Base64` + `ConcurrentHashMap`）
  ② 密钥在 `static_values`（`encodedKey`，32 字节 base64）③ 总闸门命名 `verifyOrLaunch`
- **动作**：`verifyOrLaunch` 的 `if-eqz verified`（偏移 0x5b）→ **nop（2 字节）**
- **结果**：✅ 装机后直接进主界面，卡密流程根本不被调用
- **可迁移**：极小 dex = 解码器；`static_values` 是密钥第一藏点；`xxxOrYyy` = 总闸门
- **不可迁移**：0x5b 这个偏移、`encodedKey` 这个字段名
- **本技能实测**：`autotriage.py` 3.6 秒自动报出同一个闸门/解码器/密钥（见 SKILL.md §0 表）

## 2 · 止痛药 2.3.7（载荷层 · 不可破）

- **形态**：三层自解压 ELF（45MB → 解出 111.8MB）
- **锁在哪层**：**服务端** · X25519 + Ed25519
- **判据（三问全中）**：① 提示语 `请输入卡密` / `单码` 在 payload 里 **0 命中** → 服务端逐句下发
  ② 搜到 `Ed25519` + 验签密钥内建 → 响应不可伪造 ③ 客户端无本地判决分支
- **动作**：壳全脱净（三层都解开了），但**授权层没有本地入口**
- **结果**：❌ **架构上不可本地绕过**（不是难，是不存在这个入口）
- **可迁移**：**"证明这一层破不了"也是有效结论**；证据链 = 0 命中 + 签名内建 + 无本地分支
- **教训**：同族的 5.86 是两字节，2.3.7 是零入口 —— **同一产品、同一批作者，锁完全不同**

## 3 · 纽约 1004（商业加固 · 运行时）

- **形态**：`纽约1004.sh` = 51MB ELF（`e_type=03`）；43MB 强加密 + OLLVM + 栈式 VM + 全文件 CRC32
- **锁在哪层**：**运行时**（商业加固，**无法具名**：`.dynstr` 152 个标准符号，零厂商痕迹）
- **判据**：ELF 结构 + 熵 + `filesz=0` 段；不是靠壳名
- **动作**：**ptrace 内存补丁**（磁盘零改动）—— `0xD63F0100`(`BLR X8`) → `0xD503201F`(NOP)；`0x5400XXXX`(`B.cond`) → NOP
- **结果**：✅ 运行时破解
- **坑**：线性扫描出 140 万条假指令；unicorn 漏 auxv；镜像残缺（dump 体指纹见 `04` §八）
- **可迁移**：**具名壳不是前置条件**；判到"变形层"这一级就能动手；内存补丁绕开 CRC 自检
- **不可迁移**：所有地址

## 4 · 小熊维尼 8.2（重链接 + 注入 loader）

- **形态**：`小熊维尼_8.2.sh` = **真 shell 头（280B）+ gzip + 68MB ELF**；APS2 压缩重定位 + 自检子系统
- **锁在哪层**：授权模型 = X25519+Ed25519 握手 + 客户端布尔
- **判据**：握手密钥造不出来 → 单点 patch 无效
- **动作**：**重链接 + 注入 RX loader**（0x…）；成品是"注入"而不是单点 patch
- **结果**：✅ 断网可用
- **教训（最值钱）**：**只改总开关 → 消费路径不对**。联网强制握手的模型不能只把布尔置真，
  要建立"会话态"（否则后续请求全废）。这是"改判决"与"建立状态"的区别。
- **可迁移**：外层形态可以完全不同（同批产品三种外壳）；判据是"改一个布尔够不够"

## 5 · VS 漏打追锁（三层拆解 · 无壳）

- **形态**：`小糊涂破解.和平.VS漏打追锁.sh` = 16.7MB ELF（无二次打包）；控制流平坦化 + 表驱动分发 + 串解密；
  `驱动.zip` = **32 份** `.sh`，每份 = shell 头 + 尾随 gzip + **自解密 ELF 载荷**（覆盖 kernel 4.9→6.18，含 ColorOS/oneplus 分支）
- **锁在哪层**：三层结构；授权在 `libjinverify.so`（15 个 `nativeCard*` JNI）+ 服务端
- **判据**：控制面资源串直接给出工程图（"内核驱动模块 / 主程序启动器 / 按内核版本刷入"）；
  载荷 ELF：`phnum=4 shnum=0 无 dynamic 无 interp 0 import` + 入口在 RX 段尾（距段尾 **0xB01**）
- **把手**：`/api/v2/main-program-updates/check?variant=` —— 授权过了才下发主程序
- **动作**：预打包驱动 + 主程序编成 `offline` 版（`main()` 里硬编码 `"LOCAL-OFFLINE"`）
- **结果**：✅ 完全不需要碰 `libjinverify`
- **坑**：按 `vaddr` 直读 `.data` → 0 命中（delta `0xC000`，修正后 49,110 条物资）；多字节编码误判 51,239 条
- **本技能实测**：`payload.py` 一次剥出 32 个 ELF；`elfprobe.py` 输出与上述判据逐项吻合（0xB01 = 2817）
- **可迁移**：**把手 > 判断**（造下发物比破解判断省一个数量级）

## 6 · 快斗 6.8（服务端判决 · 零字节补丁）

- **形态**：自研 **AProtect** + 22.9MB 平坦化 `.text` + 字符串逐条加密
- **锁在哪层**：**服务端**（HTTP POST + JSON；网络 API 各只有 **1 个调用点**）
- **判据**：五问 → 有 nonce + 有时间戳 → 需要随机数回放 + 时间冻结
- **动作**：**LD_PRELOAD 真响应回放 + 时间冻结**（抓一次真流量，逐字节回放）
- **结果**：✅ **二进制零补丁**（壳、VM、平坦化、字符串全加密全部绕开）
- **可迁移**：**重放优先于改判决**（成本常数 vs 指数）；单调用点 = 单点可 hook
- **细节**：每包时间存 `PTM2` 结构（`"PTM2"|ver=2|hdr=0x20|tv_sec|tv_nsec|len|payload`），
  `tv_sec` 与抓包时 HTTP `Date` 一秒不差 —— 这就是"限时卡密变永久"的开关

## 7 · CG 范围（极加密 · 密钥源打桩）

- **形态**：原版 = **极加密 t3yanzheng**（整体加密，98.3% 密文，仅 192 KB 壳桩）；破解版 = **内存 dump 重建** + 第二层 mmap 载荷
- **锁在哪层**：**本地** · 五个 `!= 0` 判定 + 密钥源被替换成常量 `0xA5`
- **判据**：`0x10B94` 返回 `0xA5`（`mov w0,#0xA5; ret`），返回值进 `eor` → **它是密钥不是桩**；
  判定厚度 = 五次 `cmp x,#0`（0x14440/0x14454/0x14468/0x1447C），不验内容/签名/时间
- **动作**：一次 XOR 解出云端配置地址（51 字节密文 → `?qq_aio_chat_type=2`）；卡密模块整块成孤儿
- **结果**：✅ 本地判决，改密钥源即可
- **可迁移**：**"密钥从哪里交出来"与"加密多强"正交**；`mov wX,#imm; ret` 看调用者定性
- **不可迁移**：`0xA5`、0x10B94

## 8 · 死伤范围（极加密 · 授权层被摘除）

- **形态**：原版 = 极加密 t3yanzheng（43.3MB，`filesz=0` 段合计 36.1MB）；破解版 = **重建 ELF**：
  1.16 MiB 明文 + **17 MB 伪代码填充**
- **锁在哪层**：本地 · `esp_ue‖range` 三个偏移表指针 + 总开关 `byte_140194`
- **判据**：原版 6-gram 0.970 + 熵 7.86 + `FILESZ0-SEGMENT`；破解版 17MB 区 6-gram 1.000 / 引用密度 51/MB
- **结果**：⚠ 授权层（微验卡密）**整块零引用 = 被摘除**；业务逻辑全明面；
  破解形态是"**重打包 + 摘除 + 填充**"而不是单点 patch
- **可迁移**：伪代码填充是"让体积看起来对"的手段；判形态（不是判算法）才能看穿
- **本技能实测**：`elfprobe.py` 对原版输出 `FILESZ0-SEGMENT(2 段, 36.1 MB)` + 6-gram 0.970 + `XREF-NOT-TRUSTED`
- **教训**：**同厂商 ≠ 同样本**（CG 与死伤都是 t3yanzheng，坐标全不一样）

## 9 · 无原版五件套（只有成品，无原版）

- **形态**：5 个成品、无原版可比：① 假服务器（Go）② 42MB 拼接体 + VMProtect 壳 ③ T盾加固 ELF ④⑤ 两个 iOS 越狱包
- **锁在哪层**：① 假服务器：**客户端不验签**；② Nova：资源解密在客户端；③ 其余：外挂本体
- **方法**：**三工位反推**（静态判型 / 运行时观察 / 控制面串）
- **结果**：三件都定出结论；**四次误判写进失败教训**
- **四次误判**：① 工具常量判反了 ② 熵误判（把混淆流当密文）③ 数错文件（把 wrapper 数量当载荷数量）④ 归因错（把第三方库行为归给目标）
- **可迁移**：**没有原版时，成品本身就是"答案"**——diff 出"没改什么"比"改了什么"信息量大
- **iOS 侧附带判据**：判代先看"目标进程里有没有你的模块"；`framework` 目录先数二进制
  （5 个里 4 个是空壳 plist）；`LC_LOAD_DYLIB` 排在 `LC_CODE_SIGNATURE` 之后 = `insert_dylib` 指纹

## 10 · 起源 3.1（零修改运行时打桩 · 明知有 VM 不逆 VM）

- **形态**：APK 26.2 MB（debug 签名）投送 → 32 份"驱动"（其实是 NDK r29 编的**用户态 PIE**，`e_type=3`，不是 `.ko`）
  → 载荷 `qiyuan_src.sh` 67.4 MB：45 MB 无 section 加密区（熵 7.99~8.00，`0x8a50` = 统一解密入口）
  + 9.6 MB 正常段 + 9 MB 明文 `.text` + `.AnProtector.sdk` 段（存 vtable 项）
- **锁在哪层**：**载荷面 · 本地**（到期三元检查 + 授权模块虚函数 + 300s 心跳）
- **判据**：函数入口 = 20 指令加密跳板（`adr x16` + `ldr w9,#imm` + `sxtw` + `add` + `br x17`），
  12 个跳板全指向 `0x8a50` 但各带 16 字节密文块；`.rela.plt` 326 条（`slot[29]=alarm`）；
  `FL=0x4060cb4` 全量 236 万条指令只有 3 处引用；`R_AARCH64_RELATIVE` 有 4 条指向跳板头 → 虚函数
- **致命约束**：破解者 README 第一条 `DISK ELF NEVER PATCHED` —— 载荷在"驱动已链接"后**读自己的磁盘文件**
  做一致性核对，静态改盘 = SIGSEGV。**改不了文件 → 只能改内存 → 只能找函数边界**
- **动作（12 个点，全在内存里）**：
  - 阶段 A（等 `驱动已链接` 后）：J1/J2/J3 三条到期分支 `nop`；R1 `mov w0,#1→#0`；R2 `cset w0,hi→mov w0,wzr`；
    `FL` 每 10s 写 0（喂狗）；O1 `br x17 → mov w0,#1; ret`（跳过 `qy21.json/QYCFG2` 云配置解析）
  - 阶段 B（等 `请输入卡密` 后）：B1/B4 `mov w0,#0; ret`；B2 **16 字节**（`mov x8,#0x7fffffff` + `str x8,[x1]`
    + `mov w0,#0` + `ret`，UI 显示"到期 2038-01-19"）；B3 `mov w0,#1; ret`；
    B5 **PLT 打桩**（`slot[29] → alarm` 改 `mov w0,#0; ret`，全进程自毁定时器失效）；ST `ret`（跳过 5 分钟 stall）
- **结果**：✅ 12 个内存补丁，**磁盘零改动**；`spawn.sh` 每 10s 喂狗，跑到 `ALIVE t=360` 仍在
- **最值钱的一条**：破解者**明确知道目标里有 VM（还验证了 native r0 与 VM r0 同步），但没有去逆 VM** ——
  因为 VM 只保护函数体，而他要的是"函数返回什么"。这判断省掉的工作量是本案 90% 的价值
- **可迁移**：五个不变量（ABI/调用图/值域/时序/完整性）→ 见 `11-runtime-patching.md`；
  **本技能实测**：`rkprobe.py` 15 秒扫完 67 MB，5 个真补丁点（B1/B2/B3/B4/O1）全部命中、
  `FL` 命中、`alarm` 命中、4 条 `RELATIVE→跳板` **4/4 命中**
- **不可迁移**：所有地址、`0x7FFFFFFF` 这个值、线程/周期参数

## 11 · 章鱼哥（蛮加密 MANG v5 · 追加容器）

- **形态**：7 个 `.sh` 实为 AArch64 ELF（1.92 MB / 1.27 MB×6）；**同一个明文 loader + 七个不同的尾部加密容器**
- **锁在哪层**：载荷面 · 容器（不是整文件加密）
- **判据链**：ELF 影像止于 `0x171DB`，之后仍有未覆盖区 → 节表半抹但原位在 `0x171E0`（24 项）
  → 魔数 `ROTFLKP5`（头 12816 B）+ 末 32 B `MPFOOTER` + `in_size/out_size` 三段闭合
  → 7 份 `e_entry` 全 `0x34F8`、`phnum=10`，体积差 0.65 MB **只在容器**
- **剥层链（按 loader 函数坐标）**：`iv_wrapped` → `sub_14030(IVWRAP)` 解 IV1 → 微型 VM `sub_C030→sub_133F8` 派主密钥 MK
  → `sub_13EB4` 派 `DUALAES1/2` → `sub_11C60`+`sub_11530` 标准 AES-256-CBC 按 `chunk=0x4000` 解密
  → PKCS#7（`pad=16`）→ zlib inflate（长度 `== out_size`）→ **`sha256(明文)==hdr[0xEC..]` 终检**
- **结果**：✅ **7/7 一次通过**，各过五道校验，产出 7 个明文可执行版；真机实测正常
- **七版本差异**：`in_size` 1,804,576/1,154,768/1,155,680/1,155,680/1,156,192/1,158,576/1,158,544；
  `out_size` 2,826,104/2,302,712/2,304,568/2,304,568/2,305,832/2,311,696/2,311,664
- **四条坑**：① 主密钥不是全 0（是 `sub_C030` 的 **out**，`pad=83` 露馅）② body 偏移 `0x1B6D0` 写成 `0x1B6ED0`
  → zlib `incorrect header check`（症似密钥错）③ `.rodata` 熵 6.87 的 2.26 MB 是**字形资源**（零字节 7.4% vs 密文 0.33%）
  ④ `KTAGV1` 按 32 B 比会假失败（只比前 16 B）
- **可迁移**：段覆盖图、节表暴力恢复、`B.cond +8` 垃圾字、域分隔符找密钥链、**五道验证里的终检**
- **本技能实测**：`container.py` 自动输出 `MPFOOTER` → `hdr_off=0x184c0` → `ROTFLKP5` → `ver=5/chunk=0x4000/nhash=0xad`，
  与人工结论逐字段一致

## 12 · Aiultra 10.18（重建体 · 卡密代码根本不存在）

- **形态**：原版 23,800,904 B（伪装 `.sh` 的 AArch64 ELF）→ 破解版 38,328,024 B；
  `entry 0x39210 → 0x1d89a40`；`.text` 358,108 → 36,337,104 B；`dynsym` 19 → 265；**零 NOP**
- **锁在哪层**：**原版文件里根本没有卡密** —— `socket/connect/send` 0 次、业务文件读 0、不吃 argv、
  解压数据 readers=0 且 `munmap` 丢弃
- **判据**：36 MB / 9,084,276 条指令扫 `adrp+add`/`adrp+ldr` 引用卡密串 = **0 命中** ⇒ 授权层**整块未链接**
- **结果**：⚠ 破解形态 = **重建 ELF**；「找恒真补丁」是白费 —— **判断代码不存在**
- **本技能实测**：`elfprobe.py` 对破解版输出 `HYBRID` + 6-gram 0.837（真代码+填充混合）；`零 NOP` 是关键信号
- **可迁移（新增三条硬判据）**：
  ① **零引用 ⇒ 授权层未链接**（找恒真补丁/xref/NOP 全白费）
  ② **零 NOP ⇒ 没打补丁 ⇒ 手法是重建体**（去比对段布局，不要在字节里找 diff）
  ③ **结构 diff 三型**：补丁（±几字节）/ 注入 loader（+几百 KB）/ 重建体（**±50% 体积**）
- **缺口（诚实）**：标题写"内核辅助"，但正文**没有内核侧脱壳步骤**；真要用户态拿不到的是 **LZ4 前置字典**
  （真机输出缓冲前有已映射内存充当字典），不是内核模块

## 13 · 王者减 CD 1.0.5（脚本层 Lua · 复刻原证书）

- **形态**：APK 33,019,736 B（AppLua 脚本壳，dex 8 MB 未加固）；授权与载荷都在 `assets/☁️.lua`（305,748 B 源码 + 替换密码混淆）
- **锁在哪层**：**脚本层** · `if f.code==1 then`（服务端签名只保护"来源真实"）
- **判据链**：`卡密` 在 dex 0 命中 → `resources.arsc` 唯一 CJK 命中 `R.string.user_login=0x7f13045e`
  → 引用者 `ComposeType(…, Lorg/luaj/vm2/LuaTable;, …)` ⇒ UI 由脚本渲染 ⇒ 闸门在 `.lua`
  → 加载点 `Landroid/ext/v4;->onClick → readAssetsFile("☁️.lua") → MainService.executeScript`（**唯一 1 处、无 hash/签名校验**）
  → 四串（`/api/` `code==` `token` `heart`）只命中 `☁️.lua` ⇒ 无第二道卡密
- **破替换密码**：六件件抓齐 —— 数字变量 `C6 B3 Q5 V4 t0 F2 q7 u1 y9 r8`、字母表 174 单字节、token 表 174 条、
  轮转 `_DS.s=875 ⇒ A=5`、解码器 `n(d)=a[(x[t]+5)%174+1]`、第二张表 `I` 269 条（含 `:reverse()`）
  ⇒ 305,748 B → **261,895 B 可读 Lua**
- **最终补丁（全包只改一个文件，4 处首行插入，不改判定表达式）**：
  `oo()@274431 do return true end` / `Bp()@294189 do return end` /
  `Mo(d,G,A)@286904 do return 1,'登录成功' end` / `co()@285579 do return 'ok' end`
  （305,748 → 305,831 B；关键字块平衡 原(17,4)==补(17,4)）
- **三处必须同改**：有 **30s 心跳**，只改 `Mo` 会 30 秒后被 `ko()` 停服
- **重打包**：`build_apk.py` 3279 条逐条复制 → `zipalign -p -f 4` → `apksigner`（v1/v2/v3, min-sdk 15）；

  用户实测任意卡密 → 登录成功 → 功能可用

## 14 · LV 无畏契约追锁（APK 三关连破 · 一条 B 拿下）

- **形态**：`LV.apk` 10.14 MB（Compose/Kotlin 壳）；真身在 `assets/payloads/program/LV-VALORANT-KERNEL`（11.4 MB ELF）；
  37 份 `.ko` 在 `assets/payloads/drivers/{A,B}/`。旧版是 `.sh`：10 行 shell 头 + `owo→w` 文本变换 + gzip（`tail -n +11 | sed 's/owo/w/g' | gunzip`）
- **判据**：dex 里搜不到 `kami`/卡密字样，但有 `chmod`/`su`/`insmod`/`ProcessBuilder` ⇒ **dex 只是加载器**
- **四道门（链式，按顺序撞）**：① 卡密（服务端签名+时效）② 强制更新（`updatemust=='y'` → exit）
  ③ SHA-256 载荷校验 ④ **网络硬依赖**（断网时把错误文本当响应 → hex→RC4→json::parse 抛异常 → terminate）
- **响应解码链**：`hex 解码(sub_B7EC8)` → **标准 RC4**（key 字面量 31 字节）→ `json::parse`
- **最终补丁 v9（7 处）**：
  1. `0xBB1A8` `B.EQ loc_BD118` → `nop`（强制更新永不触发）
  2. `0xBC014` `TBZ W20,#0,loc_BC934` → `nop`（登录结果恒成功）
  3. `0xBA350` `MOV W8,#0x6E63` → **`B 0xBC018`**（整段跳过公告/更新/登录）
  4. `classes.dex` 文件偏移 `0x9600C` `38 02 35 00` → `00 00 00 00`（APK 侧载荷校验恒通过）
  5. dex 头 `0x08/0x0C` 重算 Adler-32 / SHA-1（否则点开即崩）
  6. `assets/catalog/driver_catalog.json` 的 `program.sha256` 等长替换
  7. `AndroidManifest.xml` versionName/versionCode `1.0/1` → `9.9/99`
- **结果**：✅ 设备端见证；**飞行模式下同样输出**（网络依赖彻底摘除）
- **九条失败教训（每条都真实发生）**：① 只破卡密没管更新门 ② 换载荷没同步清单 ③ 改 dex 没重算头部（点开瞬间退出）
  ④ 只改 versionName 不改 versionCode（装了几次都是旧版）⑤ 自写 stub 漏写字符串 flag（parse empty input）
  ⑥ BL 立即数用 `len(code)*4` 算（跳到分配器前 4 字节）⑦ 按 31 字节 key 硬算 RC4（其实对象 size 不同）
  ⑧ 把 `json::parse` 输入指向已析构的槽（use-after-free）⑨ 用"日志没打印"推断"没走到"（stdout 有缓冲）
- **用户侧判据**：提示"找不到 com.tencent.tmgp.codev / 连接失败" ⇒ **先核对目标包名与进程是否在跑**，
  不是改二进制（它重试约 24 次后 `Abort(134)`，看着像崩溃，其实只是没找到人）
- **本技能改造**：`patch_dex.py` 已升级为**三步一体**（指令 + SHA-1 + Adler-32 + 解析器自证），直接落这条教训
