# 防守方地图 — 从「防破解规范」反推的攻击面

> 有人写了一份《软件工程安全防破解》规范（LLVM 混淆/虚拟化、服务端鉴权、WebSocket 心跳、TLS/AEAD、
> nonce 防重放、反调试、注入与 Hook 检测、跨平台完整性），**连验收清单一起公开了**。
> 这份东西对我们是**对手的自白书**：它列出的每一条"必须做到"，反过来就是"没做到就能被打"；
> 它明确承认覆盖不了的，就是我们首选的下手处。
>
> 本文件只做一件事：**把防守项翻译成攻击切入点**。看懂了就不用再猜对方下一步加什么。

---

## 一 · 他们自己承认「挡不住」的四件事（**优先打这四条**）

验收清单第 7 节原文承认这些"不能完全覆盖"：

| 他们承认挡不住的 | 我们的打法 | 落在本技能哪 |
|---|---|---|
| **代码段外 Hook** | 只校验 `.text` 的哈希挡不住 **PLT/GOT/vtable/数据段** 的改写 —— 这正是运行时打桩的落点 | `11-runtime-patching.md`（形态 D：PLT 打桩） |
| **手工映射** | 不走 `dlopen`/`LoadLibrary`，自己 mmap + 重定位 + 跳入口 ⇒ 模块枚举（`/proc/maps`、`dl_iterate_phdr`）看不到你 | `11` §六（走 `/proc/pid/mem`，不 attach） |
| **检测器自身被修改** | 打"检测逻辑"而不是"被检测的值"：改 `if (flag) exit` 的调用点，或喂狗让 flag 永远 0 | `11` §五（喂狗 vs 拆狗） |
| **TOCTOU**（检查与使用之间的时间差） | 校验发生在 A 时刻、使用发生在 B 时刻 ⇒ **在校验之后、使用之前改**（先过校验再翻值）；或用输出门同步卡时序 | `11` §四（用输出门分阶段打桩） |

> **一句话**：完整性校验保护的是"某个时刻的某个区间"，攻击打的是"别的时刻 / 别的区间"。

## 二 · 他们列为「不够」的做法 = 我们的捷径

规范里那些"光这样做不行"的表述，说明实践中大量实现**只做了不够的那一半**：

| 规范原文（他们的要求） | 说明现实里常只做到 | 我们的入口 |
|---|---|---|
| "将客户端 `isLicensed`/`isAdmin` 或 UI 状态改为成功，**不能绕过敏感接口鉴权**" | 很多实现只改了 UI 就以为加固了 | 先测：改本地布尔 → 敏感接口还通不通？通 ⇒ 服务端没独立鉴权 ⇒ 一条补丁 |
| "**时间戳或随机响应字段未被当作唯一防重放手段**" | 大量客户端只比时间戳 / 只比 nonce 回显 | 只要"新鲜度"只有一个维度，就有窗口：改本机时间 / 冻结时钟 / 回放缓存的合法响应 |
| "挑战需绑定会话、请求、用途、有效期与完整性" | 常只绑了会话，没绑"用途/请求体摘要" | **改用途/改字段**就能让同一份响应用于别的接口（REPLAY-03） |
| "同一挑战并发消费最多一次，多实例一致" | 单实例用内存 Map 去重，多实例/多进程就漏 | 多开、并发、切网络重连 —— 找"第二次也成功"的窗口 |
| "服务端重启/存储故障时不会让旧挑战重新有效" | 防重放表存在内存里 | 触发重连/让服务端重启（弱网、切换代理）→ 旧挑战复活 |
| "幂等键不是 nonce" | 两者混用 | 同一请求重复提交，看业务副作用是否重复 |
| "AEAD nonce 与业务 nonce 分离" | 复用同一个随机源自增 | nonce 复用 ⇒ 可拿两条密文 XOR 推密钥流（CTR/GCM 同 nonce） |
| "客户端不能通过**缓存心跳或自报时间**永久在线" | 客户端确实这么做了，服务端没校验 | 缓存心跳 + 冻结时间 ⇒ 断网仍在线（`05` §三 四件套） |
| "字段拒绝歧义：重复键、类型混用、非规范编码" | JSON 解析器各取一个（首/末） | **重复键攻击**：`{"vip":false,"vip":true}` —— 客户端取后者、服务端取前者 |
| "不以文件名作唯一依据"（DLL 检查） | 实现里就是按文件名黑名单 | 改名 / 换路径 / 侧加载同签名合法 DLL |
| "签名清单绑定版本/架构/模块身份" | 只校验哈希，不绑版本 | 跨版本移植旧模块；或用旧基线通过检查 |

## 三 · 心跳状态机 → 三个可打的窗口

他们的状态机契约（§2）写得比多数实现严格。**实现通常只覆盖第一行**：

| 状态 → 事件 | 他们要求 | 大多数实现的实际行为 | 我们的窗口 |
|---|---|---|---|
| 未鉴权 → socket 建立/Ping | 只证明链路，不能开放敏感操作 | 有实现把"连上"当成"已授权" | 直接构造连接，不发登录 |
| 已鉴权 → **缺失/超时/断网** | 进入**有上限的**宽限或立即受限 | 宽限没有上限，或干脆本地计时 | 冻结时钟 / 断网 → 永久宽限 |
| 宽限 → 恢复网络 | 重新核验会话与新挑战 | 复用缓存结果 | 重放上一次成功响应 |
| 任意 → **登出/撤销/主体切换** | 旧请求、连接、定时器、租约全部失效 | 旧定时器还在跑 | 用**旧心跳**续新会话（HB-04） |
| 在线 → 原生 Ping 正常但业务授权过期 | 敏感操作必须失败 | 只看连接活着 | 这正是"只改登录闸 30 秒后被踢回"的根因（`08` 起源/LV） |

> **判据**：把心跳当"授权闸"还是"链路保活"？前者要打三处（登录/心跳/环境），后者只打登录。
> 看它心跳失败后的行为：只是重连 = 链路保活；直接停功能 = 授权闸。

## 四 · 他们的验收清单 → 我们的攻击用例（逐条镜像）

| 他们验收（编号） | 我们的攻击动作 |
|---|---|
| AUTH-01 未登录/过期/撤销/错角色访问敏感接口 | 用过期/别人的凭证直接打接口，看服务端是否真拒 |
| AUTH-02 改客户端布尔值 | 改 `isLicensed`/`isAdmin`/UI 状态 → 看敏感接口 |
| REPLAY-01 回放旧登录成功响应 | **首选**：抓一次真流量，原样回放（`05`） |
| REPLAY-02 同一挑战发两个实例 | 多开 / 并发 / 双进程 |
| REPLAY-03 改用途/请求体/主体/到期/result/key_id | 逐字段改一个，看哪个字段没被绑定 |
| REPLAY-04 消费后重启 / 存储失联 / 存储满 | 弱网重连、清缓存、触发服务端漂移 |
| CRYPTO-01 改标签/密文/AAD/证书 | 看是否降级明文（有实现把验签失败当"无加密"继续） |
| CRYPTO-02 并发/重启/密钥轮换/计数器回绕 | 找 AEAD nonce 复用 |
| HB-01 Ping 活但授权过期 | 只冻结授权相关时间，看功能是否还活 |
| HB-02 无 Pong/半开/网络切换/代理断连 | 制造半开连接，看宽限多久 |
| HB-03 休眠/唤醒/后台节流 | 挂后台、休眠，回来是否仍在线 |
| HB-04 撤销/主体切换/旧定时回调 | 用旧会话的定时器续命 |
| INPUT-01 重复键/超长/类型歧义/未知版本 | JSON 重复键、类型混用、超长字段 |
| UPDATE-01 旧客户端 × 新服务端 | 降版本客户端连新服务端，看有没有旧路径绕过 |

## 五 · 混淆与虚拟化的"覆盖漏洞"（他们自己要求列清单）

验收清单第 6 节要求："应用自有模块总量、**已保护范围和排除项有清单**；宣称全程序时有完整覆盖依据"，
并且"**不支持的第三方 / FFI / JIT 区域明确列出**"。

翻译过来就是：

1. **一定有未保护的区域** —— 第三方库、FFI 边界、JIT 生成的代码、动态加载的插件。
2. **找这些区域的方法**：按模块/段算覆盖率（`elfprobe.py` 的段熵 + `13` 的容器判据），
   哪个段熵是明文但它在做"真活" ⇒ 那就是排除项。
3. **别在 VM 里硬啃**：VM 只保护函数体，入口/出口仍明文（`11` §一）。

> 他们的自检项"能在真实产物中验证自定义指令表示/VM 分发运行时，不以普通混淆、去符号或压缩冒充虚拟化"
> 反过来告诉我们：**大量标称"虚拟化"的东西只是混淆/压缩** —— 先用 `elfprobe` 判形态（`04`），别上来就逆 VM。

## 六 · 完整性校验的四个可绕点（他们列的"需处理"就是我们的"可打"）

| 他们要求处理的 | 没处理好时的攻击 |
|---|---|
| "签名清单绑定**版本/架构/模块身份**" | 不绑 ⇒ 跨版本/跨架构移植旧模块 |
| "旧基线、未知构建、网络中间人替换均拒绝" | 不校验版本号 ⇒ 用旧构建（漏洞版本）过校验 |
| "ASLR、重定位、导入修复、**合法动态代码及虚拟化运行时变化**不造成误报" | 他们为了不误报，往往放宽哈希范围 ⇒ **放宽的那部分就是我们的落点** |
| "更新后新代码使用新基线，旧版本兼容、撤销及回滚" | 回滚策略不清 ⇒ 降级到旧版本 |

## 七 · 反向借鉴：他们的交付纪律 = 我们的验收纪律

这份规范最值得抄的不是技术，是**纪律**：

| 他们的表述 | 我们对应 |
|---|---|
| "工具截断 / 缺少引擎 / 找不到匹配均不能记为通过" | 我们：`DCB` / 0 命中 / 工具报错 ≠ 结论（`09` B 类） |
| "没有执行不能填写通过；未授权访问生产不能记为线上已验证" | 我们：没装机看到主界面 ≠ 交付（`07`） |
| "区分源码、静态产物、运行观察、推断和未知" | 我们：observed / inference / unknown 三级 |
| "不承诺无法逆向或防住 99% 破解者" | 我们：不承诺"一定破得了"，卡在第几层就报第几层 |

## 八 · 怎么用这篇（一句话）

拿到目标后，**先按他们的清单逐条问"这一项它做到没有"**：

```
登录/授权：服务端独立鉴权？还是只改 UI 就行？
新鲜度：绑了几维（会话/请求/用途/有效期/完整性）？只有时间戳 ⇒ 有窗口
心跳：链路保活 还是 授权闸？宽限有没有上限？
混淆/虚拟化：真 VM 还是普通混淆？覆盖到什么范围？排除项在哪？
完整性：校验哪个段/什么范围？绑版本架构吗？放宽了哪部分？
```

**答不上来的那一格，就是第一刀的位置。**
